# i18n Design — Norwegian/English Portfolio

## Vision
Show all UI text and content in the user's language. Auto-detect from browser, allow manual override via a toggle in the header. Support Norwegian (no) and English (en).

## Architecture

### i18n Module (`scripts/i18n.js`)
Central module exporting:
- `getLang()` — checks localStorage first, falls back to `navigator.language` (nb/nn/no → 'no', everything else → 'en')
- `setLang(lang)` — saves to localStorage, updates `<html lang>`, calls `updateDOM()` and registered re-render callbacks
- `t(value)` — if value is `{ en, no }` object, returns the correct language string. If plain string, returns as-is.
- `updateDOM()` — finds all `[data-i18n]` elements, looks up translation key, sets textContent
- `onLangChange(callback)` — registers callbacks for JS-rendered content that needs re-rendering

### Translation Files
- `scripts/translations/en.js` — English UI strings
- `scripts/translations/no.js` — Norwegian UI strings

Keyed by dot-path: `header.subtitle`, `nav.projects`, `contact.title`, etc.

### HTML Strategy
Static strings get `data-i18n="key"` attributes:
```html
<p data-i18n="header.subtitle">Developer & Content Producer</p>
```
`updateDOM()` replaces textContent with the translation for the active language.

### JS Content Data Strategy
Project data arrays use `{ en, no }` objects for translatable fields:
```js
{ description: { en: 'Interactive 3D platform...', no: 'Interaktiv 3D-plattform...' } }
```
Render functions call `t(item.description)` which resolves to the correct language.

Fields that are proper nouns (titles, artist names, company names, tech names) stay as plain strings.

### Language Toggle
A `NO | EN` button in the header near navigation. Calls `setLang()` on click.

### Re-rendering
When language changes:
1. `updateDOM()` handles all `data-i18n` elements in HTML
2. Registered callbacks re-render JS-generated content (project cards, timeline)
3. `<html lang>` attribute is updated

## What Is NOT Translated
- Artist names, song titles, band names
- Company names (Cavai, Wolve IT, etc.)
- Technology names (Vue.js, TypeScript, etc.)
- Project titles that are proper nouns
- URLs, email addresses
